# Notes on the new state of the Zuri programming language.

- Numbers and Booleans are now objects with methods. Numbers carry methods such as `log`, `sin`, `abs`, etc.
- All objects and classes now carry a default `to_string()` method that can be overridden by their implementations.
- Builtin functions such as `to_string`, `to_number`, etc have been made redundant new features and have been removed.
- Anonymous functions now have an alternate syntax that uses the `def` keyword directly instead of using the `@` sign which has now been marked as a shorthand. i.e. We can now have `def() { ... }` instead of `@(){ ... }` and `def {}` instead of `@{}` where the `@` notation now becomes the shorthand.
- The class constructor has been replaced by the `@new` decorated method instead of a method with the same name. 
- Classes are now partially-immutable. Once created, new fields and methods cannot be added at runtime. However, their static properties can continue to be mutated.
- Class operator override have now been replaced and no longer have their own distinct syntax. Now, they reuse the decorated methods such as `@add`, `@sub`, `@mul`, `@div`, `@lshift` etc.
- `@eq(other)` defines `==` for a class, and `!=` is its negation. It runs when the left operand is an instance of the class and the right operand is an object too, so `x == nil` never calls it, and it must return a bool. `using` matches through it. Lists, dictionaries, `contains()`, `index_of()` and dictionary keys still compare instances by identity.
- Imports are now local by default and you'll have to explicity specify that you intend to export them out of the importing module by prefixing the import path with the `@` symbol. E.g. `import @.module`, `import @.module { item }`, or `import @.module { * }` where module, item, and all items become exported by the current module respectively.
- `Exception` has been renamed to `Error`.
- The `zlib` module has been dropped in favor of the `compress` module which includes support for `deflate`, `gzip`, and `zlib` format that are currently supported and introduces support for `zstd`.
- The `zip` module has been moved under the `compress` module.
- The `ast` and the `reflect` module has been collapsed into a single module called `zuri`.
- `template` module has been renamed and moved to `wire` module.
- The `socket` module and `ssl` module has been dropped in favor of the `net` module.
- The `postgres` and `sqlite` module have been replaced with the respective submodules of the new `sql` module. The `sql`.
- The `curl` module has been removed from Zuri.
- The `env` module has been added to the standard library. It reads a `.env` file into the process environment and reads values back out converted to the type the program wants.
- The executable no longer runs a bare path. `zuri` alone is still the REPL, `zuri run [path]` runs a script, a package directory, or the working directory's own `index.zu`, and any other first word names a command. Commands are a directory with an `index.zu` or a `.zu` file, looked up in that order, resolved from the `cmds` directory beside the runtime first, a project's `.zuri/cmds` second, then the `cmds` of the packages installed in the project, and last those installed for the user. A name that starts with `_` is never a command, so a command's shared code can sit beside it as `_shared` or `_helpers.zu`. Two installed packages providing the same command is refused rather than settled by chance. Everything after the path or the command name is forwarded to the program, so `os.args` reads the same in both cases. `zuri --version` reports the build and `zuri --help` adds the commands available from here, both taking a short spelling (`-v`, `-h`) and running nothing. A command names and describes itself with `@command` and `@description` in its doc block, which is what the listing reads. The banner, the usage lines and the listing headings are coloured the same way a command's own `args` help is, and everything the runtime prints goes plain when `NO_COLOR` is set or the stream is not a terminal.
- The `http` module now has server-side sessions. `http.session()` is middleware: it finds the session named by a cookie, hands it to the handler through `request.session()`, and writes it back when the response goes out. A request that never touches its session reads nothing, writes nothing and sets no cookie; the record exists from the first write. Sessions carry values, a one-request flash, `regenerate()` for the identifier rotation a sign-in needs, and `destroy()` for signing out. They expire on two clocks, a rolling idle timeout and an absolute lifetime. Storage is a `SessionStore`: `FileStore` (the default, in a private `0700` directory under the platform's temporary directory), `MemoryStore` for tests, and `SqlStore` from `http.session.sql`, which is a separate import so the `sql` module is not loaded by a server that does not want it. The store is keyed by the SHA-256 of the identifier rather than the identifier, so its contents cannot be replayed as cookies, and setting a `secret` signs the cookie so a forged one is refused before the store is touched.
- A class now inherits from an expression rather than a bare name. The parent in `class Child < Parent` may be any expression that starts with an identifier, so a class reached through a module (`class Store < http.session.SessionStore`), an entry in a dictionary, or the return value of a call all work. The same holds for the target of a class extension. It is evaluated once, where the class is declared.
- A `def` now scopes like a `var`. At the top level of a file it binds a module-level name; written inside a function or any other block it binds a local of that block, and it goes away with it. Helpers declared beside each other in one block can still call each other in either direction, because their slots are reserved before any of their bodies compile, but the function itself only exists once its declaration runs.
- An imported module now crosses an isolate boundary. It is reloaded on the receiving isolate rather than copied, so the recipient gets its own instance with its own top-level state, and a function that captures a module (which a nested helper using an import always does) can be spawned. An open file is the one value left that cannot cross.
- `zuri init [path]` scaffolds a project: `project.toml`, an `index.zu` that re-exports `app` and starts it behind `if __root__ == __file__`, an `app/index.zu`, a `tests/app.test.zu` that passes, a `README.md`, a `.gitignore` and a `.gitattributes`. With no path it initializes the working directory. In a terminal it asks for the name, version, description, author, license, keywords, homepage and repository, offering a default for each and showing the manifest before writing; anywhere without a terminal, and under `--yes`, the defaults stand. Every question has a flag that settles it. The name defaults to the directory's own, lower-cased and joined up, and has to be lowercase letters, digits, hyphens and underscores between alphanumeric ends; the version is semantic versioning; the author is read from `git config`. A file that already exists is kept, so initializing inside an existing directory adds only what is missing, and a directory that already holds a project is refused unless `--force`, which rewrites `project.toml` alone. `--dry-run` reports and writes nothing, and `--vcs` settles whether a git repository is created, which otherwise happens only when git is installed and nothing above is already a repository.

- The `ffi` module has been added to the standard library. It calls C and Rust libraries and is called back by them. `ffi.open()` loads a shared library by path or by bare name, completing the name the platform's way (and asking the loader's cache for the versioned file on Linux), or the running process when given none. A function is bound by name and signature with `Library.function()`, or in bulk from declarations: `ffi.declare()` reads C (typedefs, records with packing, alignment and bitfields, enums, prototypes, `extern` variables, `_Static_assert`, and the preprocessor's `#define`, conditional and `#pragma pack` lines, with the platform's predefined macros), `ffi.declare_rust()` reads a crate's C ABI surface as its source is written (`extern "C"` blocks and `#[no_mangle]` functions, `#[repr(C)]`, packed, aligned and transparent types, enums with and without fields in `repr(C)` and primitive layouts, aliases, consts, statics and `#[cfg]`), and `bind()` turns a set of declarations into a namespace of callable functions, variable pointers, constants and types. Records are laid out as the platform's C compiler lays them out and pass by value in whatever registers its calling convention assigns them. Every value is converted and checked at the boundary: integers are range-checked, 64- and 128-bit ones beyond 2^53 are bigints, a record is a dictionary, a string passed to a `char *` is a temporary NUL-terminated copy, bytes pass their own storage, and a list or dictionary passed to a pointer is written back afterwards unless the pointer is to `const`. `Pointer` reads and writes native memory; what the module allocates is bounds-checked and refuses use after `free()`, and `own()` takes over memory C allocated with the function that releases it. A Zuri function passed to a function pointer is a callback for that call, `ffi.callback()` makes one that lasts until `release()`, an error raised inside a callback is raised again once C returns, and a callback called from another thread runs on the isolate that made it; `ffi.threaded()` runs a foreign function on a helper thread so the isolate can answer its callbacks meanwhile. Variadic functions take extra arguments typed by their values or with `Type.of()`. `errno` and `GetLastError()` are captured around every call. `ffi.link()` links static libraries, Rust staticlibs included, into a cached shared library with the platform's linker. Types, pointers, libraries and functions cross to other isolates without being moved.

- Package management ships with the runtime. `zuri install`, `uninstall`, `update`, `restore`, `info`, `search`, `publish`, `yank`, `owner`, `account` and `clean` work on the project around the working directory, the nearest directory holding a `project.toml`. Dependencies are declared in `[dependencies]` and `[dev-dependencies]` with semantic version ranges (a bare version is a caret range), from a registry, a git repository or a path. Every package gets exactly one version, chosen by a PubGrub resolver that explains a conflict step by step, and `project.lock` pins every package to an exact version, source and checksum. Packages install into `.zuri/libs` under their import name, hyphens made underscores, staged and swapped in whole so a failure changes nothing. A dependency's install scripts run only when `[install] allow-hooks` names it. `--global` installs into `ZURI_HOME` (`~/.zuri` by default), and a global package's commands get launchers in `ZURI_HOME/bin`. `ZURI_REGISTRY`, `ZURI_TOKEN`, `ZURI_TOKEN_<ALIAS>` and `ZURI_CACHE` configure the client from the environment.
- Memory a program frees goes back to the system. The allocator returns freed memory after 10 ms (`MIMALLOC_PURGE_DELAY` overrides it), `zuri.reflect.gc()` returns what it frees before it returns, and a thread that has waited a second in `recv()`, `select()`, `join()`, `wait_any()`, `wait_all()` or for its next pool task collects its garbage and returns that memory too, so an idle server or an isolate parked on a channel sits at its working size rather than its peak. Equal short strings in one isolate message arrive as one shared object.
- `zuri lsp` is the Zuri language server, written in Zuri. Editors that speak the Language Server Protocol get completion, hover, signature help, go to definition and the rest of navigation, references, rename, diagnostics as you type, quick fixes, extract and inline refactorings, formatting through `zuri fmt`, semantic highlighting, inlay hints, code lenses, call and type hierarchies, and the tests the `test` module declares, found and run from the editor. The book's Editor Support chapter covers every feature, the settings, and setup for Visual Studio Code, Neovim, Helix, Sublime Text and Emacs.
- `string.match()` returns the capture groups of the first match, as the original runtime did: the whole match under `0`, each group under its number, a named group under its name too, and `nil` for a group that takes no part. Code reading only key `0` is unaffected.
- A relative import can climb more than one directory: each `..` is one directory up, so `import .. ..shared.config` is two up and `import .. .. ..shared.config` three. The dots may also be written together, `import ....shared.config`, which the parser reads the same way, two dots to each directory.
- `import` now resolves a bare name through the project's `.zuri/libs` first, then the standard library, then the native modules, then the packages installed for the user in `ZURI_HOME/libs`. The project is found from the script `zuri run` was given, or the working directory for a command or the REPL, once when the program starts, so a program imports its own project's packages whatever directory it is started from.
- `zuri serve` runs Nyssa, the package repository: the registry API the package commands speak and a website for finding packages and managing accounts and tokens. It stores its data in SQLite by default, or PostgreSQL, MySQL or MariaDB through a connection string, applies its migrations when it starts, and takes every setting from a flag, a `NYSSA_` environment variable, or `nyssa.toml`. Passwords are Argon2id hashes, tokens are scoped, expiring and stored as digests, sign-in failures lock an account across every worker, forms carry CSRF tokens, and every uploaded archive is checked before it is stored. `zuri serve admin` creates accounts for a closed repository and appoints administrators, who may yank any version and change any package's owners.
- `zuri bundle` packages a project with a runtime into a directory, an archive, a single self-unpacking executable or a macOS application, for this platform or, with the release of the same version for it, any other. A bundle runs the project's `index.zu` from anywhere and uses nothing installed on the machine. `zuri upgrade` replaces the installation with a newer release, checked against its published checksum and swapped in whole, or not at all.
- `file(path, 'x')` and `'x+'` create a file and fail when anything is already there, the check and the creation being one step, which is what a lock file needs.
- `os.target` names the platform the runtime was built for as a target triple, the way release archives are named.
- The `http` client sends requests through a forward proxy, from its `proxy` option or `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY`, tunnelling HTTPS with `CONNECT`.
- `HttpResponse.on_finish()` registers a callback that runs once the response is final, after any error handling, and `middleware.logger()` logs from it, so a request that failed is logged with the status its client was sent.
- The `sql` capability `transactional_ddl` says whether schema changes stay inside a transaction; it is false for MySQL and MariaDB, which commit at every `create`, `alter` and `drop`. A `Transaction` now has `fetch_column()`, `stream()`, `prepare()` and `exec_script()` like a connection.
- `after_all` runs even when `before_all` failed, so a setup that got part of the way still releases what it acquired.
- The isolate pool starts its threads as work arrives, up to its size, rather than all at once.
- `zuri.parse()` returns the program as it was written. `for`, `iter` and `do` loops, compound assignment, `++` and `--`, interpolated strings, `when` arms and `{ name }` dictionary shorthand each come back as a node of their own, and every node carries the whole of the source it was read from: `start` and `end` offsets, and `line`, `col`, `end_line` and `end_col`. A declaration starts at its keyword, and a node that names something carries a `name_span` saying exactly where the name is. `zuri.parse_partial()` reads as much of a source as it can, carrying on past every statement it cannot read, and returns the tree with every syntax error, and `zuri.check()` returns every problem compiling a source would report. Both report `zuri.Diagnostic`s, a message and the span it is about, and neither raises on bad source. `zuri.doc` reads documentation comments: the prose and `@tag`s of a doc block, and which declaration each block documents.
- The `rpc` module has been added to the standard library. It is JSON-RPC 2.0 on both ends, over HTTP, WebSockets, TCP, TLS, Unix domain sockets, standard streams, child processes and pipes between isolates. `Request`, `Notification`, `Response` and `RpcError` are the messages, and `rpc.decode()` reads one, or a batch, checking every rule of the specification and refusing what breaks one with the code it is answered with. A `Service` holds the handlers given to `on_request()`, `on_notification()` and the `on_unhandled()` fallback, and `answer()` takes one message or batch and returns its answer; batches over its limit, 1000 by default, are refused whole. `rpc.http_handler()` serves a service from an `http` route, answering with `200`, `204`, `405` or `415` as JSON-RPC clients expect and handing every handler the HTTP request as `context.request`, and `rpc.HttpClient` calls one, with batches matched by id. An `Endpoint` is a service on a connection: it answers what arrives and calls the other side with `request()`, `request_batch()`, `send_request()` and `notify()`, a handler can `defer()` its answer and `reply()` later, and `listen()` reads and decodes on an isolate of its own so a program can wait on the connection beside its other channels and `dispatch()` what arrives. `HeaderFraming`, `LineFraming` and `MessageFraming` tell messages apart in a stream. `rpc.serve()` binds a listening socket and gives every connection an endpoint of its own across a pool of polling worker isolates, with TLS, idle timeouts and a clean stop.
- `db.schema` changes a database as well as describing it. `create_table()`, `alter_table()`, `rename_table()` and `drop_table()` take a table described on a `Blueprint` from `sql.blueprint`, once, and each adapter turns it into its own engine's statements, so one description creates the same table on SQLite, PostgreSQL, MySQL and MariaDB. Column types, keys, indexes, foreign keys with their actions, defaults and byte-for-byte comparison (`exact()`) all carry across; every column is required unless `nullable()` says otherwise, and indexes and keys are named for their table and columns so they drop by their columns. A change made outside a transaction runs as a whole where the engine can roll it back. SQLite carries out what its `ALTER TABLE` cannot by building the table again from its own definition, with foreign key enforcement switched off around it and checked before it commits, so rows referring to the table survive. A table another refers to is never dropped. `Transaction` has `schema`, and an adapter of one's own supplies schema changes by returning a `sql.DdlAdapter` from `Driver.ddl()`.
- `sql.migrate` applies versioned migrations: Zuri files exporting `up(db)` and `down(db)`, written with `db.schema` once for every engine, applied in version order, each in a transaction of its own with the row recording it, and rolled back by batch, by count or to a named migration. `status()` reports a migration whose file changed after it ran and one whose file is gone. Two processes migrating one database at once apply each migration once, under PostgreSQL's advisory lock, MySQL's and MariaDB's named locks and SQLite's write lock. `zuri migrate` runs them from the command line, with `status`, `down`, `reset` and `new`, reading the database from `--database` or `DATABASE_URL`, in the environment or the project's `.env`. `new` takes one or more names of letters, digits and underscores and writes a migration for each, with `up(db: Transaction|Connection)` and `down()` typed so an editor completes them.
- `sql.model` gives each table a class. A model extends `Model`, its fields are its columns, and a static `define()` names its table and key, casts, `validate` rules, unique checks, fillable and hidden columns, scopes, and its `belongs_to`, `has_one`, `has_many` and `belongs_to_many` associations. `db.model(Post)` and `tx.model(Post)` start a query that narrows without changing the one it came from, loads associations in one query each with `include()`, pages, streams, and updates and deletes in bulk. Records save, validate, reload and delete themselves through the connection or transaction they are handed, write only what changed, run lifecycle hooks in a transaction with the write, and raise `RecordInvalid`, a `validate.ValidationError`, when they fail their checks.
- Nyssa's schema is one migration written with `db.schema`, applied through `sql.migrate`, and its foreign keys now exist on MySQL and MariaDB, which ignore the column-level `references` its earlier schema used.
- A parameter annotated with a class that a selective import brought in, or that a local of an enclosing function holds, is checked against that class. It raised `UndefinedError` as soon as an instance was passed, since only a module's own globals were looked at.
- The language server reads a union annotation such as `Transaction|Connection`. Completion offers what every one of its types has, a member reached through it keeps its type when the types agree on it, and go-to-definition and hover show the member as each type declares it. Rename leaves a use through a union as it is and says so, since renaming the member on one type alone would break it for the others.
- `args` exits 1 when a command is left without its value, where it printed the error and exited 0, and `--help` after such a command shows its usage rather than reporting the value missing.
- `zuri.import_file(path)` imports a module from a path known only at runtime, through the same cache as `import`. `zuri.reflect.class_of(instance)` returns the class an instance was built from. Modules, and native functions, now compare equal to themselves; a module from `import` and the same one from `import_file()` are `==`.
- `date.parse()` reads an ISO 8601 fraction of a second as a fraction: `.5` is half a second and `.123` 123 milliseconds, where both were read as that many microseconds, and digits past the sixth are read over. `format()` writes `u` as six digits and `v` as three. A `date.Date` encodes to JSON as ISO 8601 text, and a `sql.Decimal` as a number.
- SQLite `DECIMAL` and `NUMERIC` columns read as `sql.Decimal`, as PostgreSQL's and MySQL's do, and a `Decimal` binds on SQLite. A statement cached or prepared on SQLite reports the columns its table has after a schema change, where it reported the ones it had when compiled. `split_statements()`, and so `exec_script()`, keeps a trigger's or routine's body, its semicolons included, as one statement. Dropping a table or column something still depends on raises `QueryError` on PostgreSQL, MySQL and MariaDB.
- A MySQL or MariaDB connection is described by the server it reached rather than the scheme it was opened with: either scheme reaches either server, and `driver_name()`, the capabilities and the schema changes are that server's. A MariaDB server through `mysql://` reports `json` unsupported and `returning` supported, and a MySQL server through `mariadb://` is never sent `RETURNING`. `Driver.describing(connection)` is the hook an adapter overrides to say which driver describes a connection it opened.
- The optimizing tier tests a parameter annotated with a class inline, as that class or any class descending from it, where it used to leave the whole function to the baseline tier. A call to a function with such a parameter is built into a hot loop like any other, and a class imported into the file is checked the same way.
- A function a loop made hot is no longer kept in the baseline tier by an instance it constructs once a call, outside every loop, such as before the loop starts. The construction goes through its helper, and the loop is built in the optimizing tier.
- The optimizing tier keeps track of globals one at a time. Storing a global leaves what it knows about every other global alone, a read straight after a store uses the value stored, and a loop that stores to one global no longer reloads every other one on each pass.
- Closing a SQLite connection closes everything still open on it: prepared statements, cursors, blob handles and backups, each of which raises `ClosedError` from then on and is still safe to close. With nothing left holding the database, the last connection to a WAL database checkpoints it and removes its `-wal` and `-shm` files as it closes.
- A MariaDB connection has the server keep each prepared statement's column definitions, which the server then sends only when they change instead of with every execution. MySQL has no equivalent for prepared statements and sends them every time.
- A PostgreSQL encoder registered on a `TypeRegistry` returns the value's binary form as `bytes` or as a list of byte values, and the built-in encoders return `bytes`.
- A PostgreSQL integer parameter is checked against the type the server expects. A value an `int2`, `int4`, `int8` or `oid` cannot hold raises `QueryError`, where it was cut down to its low bytes and stored as a different number. A bigint bound to an `int8` is sent exactly, and an `int8` beyond 2 ** 53 either side of zero reads back as a bigint, as it does on SQLite and MySQL.
- `bytes.append()` is compiled inline by both tiers, as `list.append()` is. A method called on a list, string, byte stream, dictionary or module goes straight to its built-in method, without first trying the path that finds a compiled method on an instance.
- A loop's on-stack replacement threshold now comes from the loop's own length rather than the function's, so a short loop in a long function, such as setup code walking a small table, no longer compiles the function after a handful of turns. A field read or write the interpreter has seen reached with something other than an instance, such as a dictionary, is never compiled to a class check, so `column.name` on a dictionary stays on its inline cache instead of leaving compiled code because some class declares a `name` field.
- A class's literal field defaults (`var x = 0`, `var name = 'none'`, `var on = true`, and a bare `var x`) are now part of the class rather than code that runs for every instance. An instance starts out with them, and only a default that has to be computed, such as `var rows = []` or a call, and every declaration after it in the same class, still runs as a field initializer. Defaults and initializers apply in declaration order down the line of classes exactly as before, so an initializer never sees a field set earlier than it was declared. Constructing an instance of a class with no computed defaults skips the initializer call altogether, in the interpreter and in both JIT tiers, including a class read out of a module, as in `date.Date(...)`.
- `is_int()`, `is_string()` and the other type predicates are compiled inline by both JIT tiers, as is a slice of a list or byte stream, which now copies the range in one go. `bytes.to_string()` reads valid UTF-8 straight through and decodes with replacement characters only when the bytes are not valid.
- `Date.to_timezone()` no longer depends on the machine it runs on. It looked up the offset from the host's own timezone, so it picked the wrong one near a DST change and raised on hosts in a zone without DST, such as `Africa/Lagos`.
- `validate`'s `after`, `after_or_equal`, `before` and `before_or_equal` rules now compare instants. They ignored each date's offset, so `2024-01-01T12:00:00+01:00` counted as after `2024-01-01T11:30:00Z`.
- A panic in the runtime now ends only the isolate it happened in, whether it happened in the interpreter or under compiled code. `join()` raises `IsolateError` and every other isolate keeps running. On the main thread it exits with code 101 and the panic message. It used to abort the whole process once the code was compiled, because compiled frames could not be unwound. A panic in a callback that C made, through `sql` or `ffi`, also stays a panic now, so no Zuri code runs on after it on the same VM.
- `os.sleep()`, the watcher's `next()`, `ffi`'s `serve()` and the `isolate` timeouts raise on a duration too large to represent, or on infinity, instead of panicking. A timeout that can be represented but lies past what the clock can reach is simply a very long wait.
- `HttpServer.listen()` serves every connection at once on its one thread. It used to run each connection to completion before accepting the next, so a client that stayed idle, sent half a request or stopped reading froze the server for everyone else. Now a loop in `http.loop`, shared with the workers of `http.serve()`, watches every connection and does for each only what can be done without waiting. A request reaches the pipeline once the whole of it has arrived, output goes out as the socket makes room, HTTP/2 sessions are interleaved with everything else, a TLS handshake advances as its bytes arrive, and `read_timeout`, `keep_alive_timeout`, `header_timeout` and `write_timeout` are deadlines on each connection. A handler still runs to completion, and a streamed body or a WebSocket still holds the isolate until it finishes. `max_open_connections` caps what `listen()` holds at once, 1024 by default, and past that connections wait in the operating system's listen queue.
- `TcpStream` and `TlsStream` have `try_read()` and `try_write()` for a socket in non-blocking mode, returning `nil` and `0` rather than raising when it is not ready. `TlsStream` also has `set_non_blocking()`, `try_flush()`, `close_now()`, and `begin_accept()` with `advance_handshake()` for a handshake driven by readiness. `net.Acceptor.take()` returns a waiting connection without waiting for one.
- A TLS handshake now gives up at the socket's read timeout. A peer that connected and said nothing used to hold it forever.
- `zuri` with no arguments now reads its session from standard input when that is not a terminal, with no banner, prompt or pager, and ends with the input. `zuri < /dev/null` exits at once, and `.exit` still ends a piped session early. A line that fails reports its error and the session carries on. At a terminal, a session now ends with an error and exit status 1 once about a minute of reads have failed in a row.
- `date.mktime()` and `Date.unix_time()` now return `-1` for one second before the epoch. It used to raise, since `-1` is also how libc reports a failure.
- The REPL now decides whether an entry is finished by reading it with the compiler's lexer. A bracket in a string or a quote in a comment no longer holds an entry open, and an unclosed single-quoted string, interpolation or block comment continues on the next line, as a double-quoted string already did. Brackets that can never balance are reported at once instead of leaving the prompt at `..`.
- Source that ends right after `$` in a string or `*` in a block comment is now a `SyntaxError`. It used to crash the compiler with a panic.
- In the REPL, `os.at_exit()` handlers now run when the session ends, not after the entry that registered them, and `os.set_exit_code()` sets the status the session ends with.
- A REPL whose terminal goes away now ends with status 1 instead of spinning at full CPU, which it did when SIGHUP was ignored.
- `\${` in a string is now a literal `${`, with no interpolation and no backslash. It used to keep the backslash. `\$` anywhere else still keeps its backslash, so a regular expression's escaped dollar is unchanged, and `\\${x}` is now a backslash followed by the value of `x`, where it used to be the text `\${x}`.
- `os.Watcher` on macOS no longer loses changes made while another path is being added or removed, so `zuri run --watch` no longer misses a change made while the program is starting up.
- On macOS the first `os.Watcher` a process creates raises its soft limit on open files as far as the hard limit and the kernel allow, since FSEvents watches only about one directory for every twelve open files the process may hold. Processes started afterwards inherit the raised limit.
- The `notify` crate behind `os.Watcher` is pinned to `9.0.0-rc.7` and should move to 9.0 once it is released. No 8.x release, up to 8.2.1, fixes the lost macOS changes, so do not change it before then.
- Compiled code runs faster, by about a tenth over the benchmarks. A recursive function that constructs no instances is compiled with one copy of itself built in, so each call it still makes covers two levels. A constructor that also sets fields to `nil`, as `self.hash = nil` does, builds its instances inline like one that only copies its parameters. Loops are laid out so going round takes no branch on the way in, a field read reuses the address of the instance's field storage, calls with more than four arguments go straight to compiled code, and dead young lists whose elements were inline cost the collector nothing. `ZURI_JIT_LOG_ASM=1` now also prints the address each function runs at.
- `zuri fmt` now breaks long lines by the Dart formatter's rules, as closely as Zuri's grammar allows, and the layout comes from the code alone: where the source broke a line inside an expression no longer matters, though blank lines between statements, and between the items of a list that opens out, are kept. Arguments, parameters, lists, dictionaries and an import's names stay on one line when they fit and otherwise take one item to a line with a trailing comma, never packed several to a line. A single function with a body among a call's arguments, or failing that a single list or dictionary, followed by at most one more argument, opens out on its own while the rest stay on the line, as in `each(items, @{` and `Text(label, {`; a call inside a call is never opened that way. Operator chains break after every operator of the loosest precedence, with the operator ending the line, conditionals break before `?` and `:` and a conditional in the last branch joins the chain, and method chains break before each call. Every continued line sits two levels past the line it continues, so a broken `if` condition no longer lines up with the body under it. A value made of operators moves after the `:` of a dictionary entry that does not fit. Empty blocks close up to `{}`. As in Dart, a list or dictionary holding a `#` comment between its items keeps the rows the source wrote it in. One thing differs from Dart on purpose: a list of numbers, with or without `nil` among them, fills its lines rather than taking one number to a line.
- `close()` on the server `http.serve()` hands a worker now stops the whole server, as the `stop` function given to `on_ready` does. It used to do nothing, so a handler that closed its server left `serve()` running. Stopping either way now has every worker close the connections it holds, after giving what they have queued a chance to go out, instead of serving each until it closed, which an idle connection could stretch to `keep_alive_timeout` or `read_timeout`. Reaching `max_connections` still serves the connections already accepted until they close.
- The Linux releases run on glibc 2.28 and later, which takes in Debian 10, Ubuntu 20.04, RHEL 8 and Amazon Linux 2023. They needed glibc 2.38 before, so most server distributions could not start them. Releases now also come for musl, as `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`. These link musl dynamically so that `ffi` can load libraries, and link libgcc's unwinder in statically, so they run on a bare Alpine with nothing added but not on a glibc system. `install.sh` picks the musl build on a system that uses musl, `zuri upgrade` stays with the build it is, and `zuri bundle --target all` builds for both. When a downloaded runtime will not start, `install.sh` reports the loader's reason.
- A build puts `libs` and `cmds` beside its binary with Cargo 1.100 and later too, which lay out build script output differently. With them, a build for an explicit `--target` or with the `production` profile left both in `target/release` instead.
- The standard library has a `markdown` module, written in Zuri. It passes every example of the CommonMark 0.31.2 specification and of the GitHub Flavored Markdown extensions, with the same HTML as the reference implementations, and adds GitHub's alerts and emoji and the extensions Pandoc made familiar: tables of contents, heading identifiers, attributes, abbreviations, definition lists, fenced divs, line blocks, superscript, subscript, highlighting, math and YAML front matter. `parse()` returns the document as a tree of nodes that transforms can change before rendering, and `HtmlRenderer` can be subclassed one node type at a time. Raw HTML is shown as text and `javascript:` links are emptied unless asked for, since Markdown is usually written by someone other than the site's owner.
- `zuri doc` builds a documentation site from Markdown pages listed in `SUMMARY.md`: a page for each chapter with the contents beside it and the page's own headings beside that, search, a page that prints all of it at once, light and dark themes, and keys to search and turn the page. Code is coloured as the site is built, so a page reads the same without scripts: Zuri through Zuri's own lexer, REPL sessions, HTML and Wire, XML, JSON, shell scripts and terminal sessions, TOML, INI, JavaScript and CSS, with a block of output joined to the code above it. Pages link to each other's Markdown files, and a build reports every link inside the documentation that leads nowhere, failing over one with `--strict`. `zuri doc serve` rebuilds the site on every change and reloads the pages open on it, and `zuri doc init` starts new documentation. The book and the standard library reference in `docs/` are both built with it and each has a `doc.toml`, so building them no longer needs mdBook: `cargo build-docs` and `cargo run-docs` run `docs/tools/site.zu`, CI runs `zuri doc` directly, and a plain `cargo build` no longer renders the book.
- `zuri doc generate` writes an API reference from the doc blocks in a project: a page for each public module, named the way it is imported, with every function, constant and class in it, its parameters, what it returns and raises, and links between names written in braces. A package's page lists every public name reached through it, wherever it is declared. The reference is documentation with a `[reference]` table in its `doc.toml`, in `docs/reference` by default, and `zuri doc build` and `zuri doc serve` write its pages again before building, with `serve` rebuilding when a module changes. Documentation inside other documentation, as a reference in `docs/reference` is inside a guide in `docs`, is built and served along with it, into the site directory of the same name, and every page's top bar links to each site, as Docs, API Reference or its title unless `[site] label` names it, with the inner site taking the outer one's logo, links and address where it sets none. `[reference]` can name the modules' directory and package, leave files out, open the front page with an introduction, and group modules into parts of the contents; a module no group reaches is a warning, which `--strict` fails over. The standard library reference is generated this way, so `docs/tools/reference` is gone and its module groups are in `docs/reference/doc.toml`.
- `imagine.Font.system()` and `Font.sans()` find the fonts installed on a Mac, in `/System/Library/Fonts`, `/Library/Fonts` and `~/Library/Fonts`. The search paths were filed under `osx`, a name `os.platform` never gives, so on macOS neither found any font at all.
- `zuri doc` follows a link from one documentation into another built into the same site, written as the path between the two Markdown files, such as `../reference/src/weather-app.md#greet` from a guide in `docs/src`: it points the link at the page that file becomes there, and checks once every site is built that the page and the heading exist, naming the documentation it leads into when it leads nowhere. Images and files in another documentation are reached the same way.
- The `http` client leaves a response with no body undecoded, so a HEAD request to a site that compresses its pages, or a `204` or `304` with a `Content-Encoding` header, no longer raises `could not decode br content`, and the headers keep describing the body a GET would get.
- `zuri doc build --external` also asks for every `http` and `https` address the documentation links to, once each, a few at a time, and warns with the page and line about each that answers with an error or cannot be reached after a second try; `429 Too Many Requests` counts as an answer, and a server that refuses `HEAD` is asked with a `GET` that reads no more than it must. With `--strict`, a broken address fails the build.
- Every version on Nyssa has an API tab beside its README: the package's API reference, written when the version is published from the doc blocks in its own archive by the generator `zuri doc generate` uses, with a page for each public module, the modules listed beside it, and links between names. The registry only parses the code. The pages are kept in the database with the version of the generator that wrote them, and a version published before, or written by an older generator, has its reference written from its stored archive the first time it is asked for. `cmds/doc/reference` takes its files from anywhere, so a caller can hand it an archive held in memory. Nyssa's pages also colour Zuri code now, in light and dark.
- `url.encode()` takes a third argument, `reserved`. It is `true` unless given, keeping the reserved characters `;/:@&$,#*()` as they always were; `false` encodes them too and keeps only letters, digits and `-_.~`, which is what one value in a query needs, since an `&` or a `#` there would end it.
- Every version on Nyssa has a Source tab listing the files it holds, each shown with its lines numbered, its Zuri coloured and every line an address of its own, and every name in the version's API reference links to the line that declares it there. Files too large or not text are said to be so, and a file is found only among the version's own. Each worker keeps the last few archives it read, so reading one file after another does not unpack the archive each time. The API reference is written again for versions whose stored pages predate the links.
- Wire's `url_encode` filter takes `reserved` as `url.encode()` does, so `{{ query|url_encode(false) }}` encodes a value whole for a query string. Nyssa's search and keyword links use it, so a query or a keyword holding `&` or `#` no longer breaks the link.
- Nyssa renders READMEs and its own help pages with the standard library's `markdown` module instead of a renderer of its own, so a README reads as GitHub reads it: emphasis that runs across a line break, bold around a link, footnotes, alerts and emoji shortcodes now come out as written. Zuri code is still coloured by its lexer, and everything is sanitised as before, with a `<script>`, `<style>` or frame removed along with what it holds. The sanitiser keeps a task list's checkboxes, disabled, and every id under `user-content-` as GitHub does, with links within the page pointed at the prefixed ids, so footnotes and a README's own contents links reach their targets while no README can take an id the page uses.
