Chapter 9 · Working with the World

Files and the Filesystem

Two things handle most of the work with files. The built-in file() function gives you a handle to a single file, and the os module covers everything else: directories, paths, globs, temporary files and environment variables.

Opening a File

file(path) opens a file for reading by default. The second argument sets the mode:

Mode Meaning
r Read. The file must exist.
w Write. Creates the file, or truncates it if it exists.
a Append. Every write goes to the end. Creates the file if needed.
r+ Read and update. The file must exist.
w+ Read and update. Creates the file, but does not truncate it.
a+ Read and append. Creates the file if needed.
x Write. Creates the file, and fails if the path already exists.
x+ Read and write. Creates the file, and fails if the path already exists.

Add b to any mode to open the file in binary mode, as in 'rb', 'wb' or 'ab'.

Use x when two programs might try to create the same file at the same time. Checking whether the file exists and creating it happen in a single step, so exactly one program succeeds and all the others fail. That's what a lock file needs.

Creating a handle doesn't touch the disk. Nothing happens until you read, write or call open().

Reading an Entire File

read() without an argument opens the file, reads all of it and closes it again. It's the one-line way to get a file's contents, and it's what you'll want most of the time.

In text mode, you get a string, decoded as strict UTF-8. In binary mode, you get bytes.

Reading in Chunks

read(length) reads up to that many bytes and leaves the handle open, so you can call it again. This is how you process a file that's too large to fit in memory all at once:

Reading six bytes at a time is only for demonstration, and in real code you'd read tens of kilobytes at a time. What matters is the pattern: open the file once, read until you get an empty result, then close it once.

Note that chunks end wherever the byte count runs out, not at the end of a line. If a chunked reader needs complete lines, it has to keep the end of each chunk and join it to the start of the next one.

Writing to a File

Like read(), write() opens the handle if it's closed, writes the data, flushes it and closes the handle again. One call writes one complete file.

size is in bytes. mtime, atime and ctime are times in seconds since the epoch, which you can pass straight to the date module. mode is the raw word that holds the permissions and the type of entry, and the stat module helps you make sense of it:

Managing Files

File handles also have truncate(length), chmod(mode), set_times(access, modify) and symlink(target).

If a handler raises an error, the error is reported on standard error and the remaining handlers still run, so one failed cleanup can't stop the others.

Paths

All of the path functions just manipulate strings, except where noted:

real_path() resolves symbolic links, and the path has to exist. abs_path() doesn't require that. expand_user() replaces a leading ~ with the home directory. path_contains(base, candidate) checks whether one path is inside another, which is the check you need before serving a file that a user asked for by name. On Windows, both path_contains() and relative_path() ignore case, the same way Windows does when it looks up names.

Temporary Files

Both functions create the file or directory and return its path. You're responsible for removing them when you're done.

Environment Variables

get_env() accepts a fallback value. environ() returns all of the environment variables as a dictionary.

Watching for File Changes

An os.Watcher is notified by the operating system as files change. It doesn't poll the files repeatedly. Instead, it uses each platform's own notification mechanism: inotify on Linux, FSEvents on macOS, ReadDirectoryChangesW on Windows, and kqueue on the BSDs. FSEvents only allows about one watched directory for every twelve files a process can have open, so on macOS, the first watcher raises the process's soft limit on open files as far as the hard limit allows.

add() accepts either a directory, which is watched along with everything inside it, or a single file. next() waits for the next event. It takes a timeout in milliseconds and returns nil if nothing happened in that time. Each event's kind is one of the following:

  • 'create': something now exists at path.
  • 'modify': the file at path was changed in place.
  • 'remove': nothing exists at path anymore.
  • 'rescan': the operating system dropped some events, so anything might have changed.

A rename is reported as a 'remove' of the old path and a 'create' of the new one. Reading a file is never reported.
