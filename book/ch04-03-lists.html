4.3 · Learning the Language

Lists

A list is an ordered sequence of values. It can hold values of any type, including other lists, and it grows and shrinks as you add and remove elements.

Lists have 40 methods, which fall into six groups: reading, searching, adding and removing, ordering, transforming and iterating. This section goes through them in that order. Throughout, keep an eye on whether a method changes the list you call it on or returns a new one. Zuri's lists have both kinds of methods, and you can't tell which is which from the name.

Reading Elements

Indexing

Indexes start at zero, and negative indexes count back from the end:

l[-1] is the last element, which saves you from writing l[l.length() - 1] all the time.

Using an index that's out of range raises an error instead of returning nil:

get() can return a fallback value, but only if you give it one. With just one argument, get(i) raises an error in the same way as l[i]:

Slicing

l[a, b] returns a new list with the elements from a up to but not including b:

You can leave out either bound. l[, b] starts at the beginning, and l[a, ] goes to the end. Negative bounds count from the end, as they do for indexes.

Slices check their bounds in the same way as indexes. If a slice goes past the end, it raises an error instead of returning what it can:

Since a slice's upper bound is exclusive, length() is always a valid upper bound. l[0, l.length()] is the whole list, and l[3, 3] on a three-element list is an empty list rather than an error.

String slicing follows the same rule, which is why Strings uses s[split_at + 1, s.length()] to mean "the rest of the string" instead of using some large number.

A slice is a copy, so changing one doesn't affect the other:

Nested Lists

A list can contain other lists, and you can chain indexes to reach into them:

grid.length() counts the rows, not the individual elements. There's no two-dimensional index syntax. grid[1, 0] is a slice from row one to row zero, so it's empty.

Combining Lists

Concatenation with +

+ combines two lists into a new one and leaves the original lists unchanged:

That's how + differs from extend(). a + b creates a third list, while a.extend(b) changes a in place and returns it. Use + when you want to keep the original lists, and extend() when you're adding to an existing list.

Repetition with *

* repeats a list a given number of times:

[0] * 5 is the usual way to create a list of a fixed size filled with a starting value, so you don't need to write a loop for it.

The count works the same way as it does for strings. Zero or any negative number gives an empty list, and a fractional count is truncated.

There's one trap to watch for. Repetition copies the elements, so when an element is itself a list, every copy refers to the same list:

A single assignment changed every row, because there's really only one row. To build nested lists, use a loop or map() instead:

Comparing Lists

== compares lists by value, element by element, however deeply they're nested:

Both the order and the length have to match. To compare two lists as sets, sort copies of them first, or use the set module described in Chapter 13.

Searching

index_of() returns -1 if the value isn't in the list. last_index_of() searches from the end:

Both methods take a second argument that limits where a match can be, so together they split the list at an index. index_of(x, n) finds the first match at or after n, and last_index_of(x, n) finds the last match at or before n. Both compare by value, so you can search a list of dictionaries using a dictionary literal.

Adding and Removing Elements

These methods change the list in place:

Method Effect
append(v) Adds v to the end
insert(v, at) Inserts v at the given position
extend(other) Appends every element of another list
pop() Removes and returns the last element
shift() Removes and returns the first element
remove(v) Removes the first element equal to v
remove_at(i) Removes the element at position i
delete(from, to) Removes an inclusive range and returns how many elements were removed
clear() Removes every element

Note that delete() takes a from and a to position, both inclusive, and returns the number of elements it removed, not the list.

Sorting and Reversing

Take a close look at those two methods. sort() changes the list and returns it. reverse() returns a new list and leaves the original unchanged. This difference is the most common cause of list bugs in Zuri code.

To sort by something else, pass a comparison function. It receives two items and returns a negative number if the first item should come first, a positive number if the second should come first, or zero to keep their current order:

You can't subtract strings, so to compare text in a comparison function, use compare(), which returns exactly what a comparison function needs: people.sort(@(a, b) => a.name.compare(b.name)).

Finding Elements

Testing Every Element

some() stops at the first element that matches, and every() stops at the first one that doesn't.

Iterating Over a List

There are four ways to visit every element, and each one suits a different situation. Choose based on what you need inside the loop.

for, When You Only Need the Values

This is the default choice. Use it whenever the position doesn't matter.

for With Two Variables, When You Also Need the Index

With two variables, you get the key first and the value second, and for a list the key is the index. There's no need to call length() or keep a counter yourself.

iter, When You Need to Control the Position

iter takes more typing, so it's only worth using when you don't simply move forward one element at a time, for example when going backward, stepping by two, comparing each element with its neighbor, or changing the index inside the loop.

each(), When You Already Have a Function

each() takes a function, which makes it easy to combine with other methods. You can chain it after map() or filter() without a temporary variable, and you can pass it a function you've already defined by name.

Pay attention to the argument order. each() passes the value first and the index second, which is the opposite of for. All of the list callbacks in this chapter, including map, filter, find, some and every, take (value, index), so there's only one rule to remember. for loops over key and value pairs, while each calls a function with each value and also tells it the position.

break and continue work in for and iter loops, but not inside an each() callback. There, return only ends the current call, not the whole iteration. If you need to stop early, use a loop instead, or find() or some(), which stop by themselves.

Combining

zip() pairs up the elements of two lists. zip_from() takes a list of lists and zips all of them together.

Lists Are Passed by Reference

Assigning a list to another variable doesn't copy it:

Use clone() when you need a separate copy. The copy is shallow, which means any nested lists inside it are still shared.

Replacing the top-level 3 only changed the copy. Appending to the nested list changed both, because both lists refer to the same inner list. If you need a deep copy, copy each level you care about yourself.
