27.2 · Sharing and Shipping

Installing Packages

Adding a Dependency

The newest version is installed and recorded in project.toml as a caret range, such as http-extra = "^1.5.0". To choose a different version, give a range. Pass --exact to record =1.5.0 instead, or --dev to add a development dependency:

Everything the package needs is installed along with it, and every package goes in .zuri/libs under its import name:

zuri init tells git to ignore .zuri, except for .zuri/cmds, so installed packages are never committed. project.toml and project.lock are committed, and together they're enough to recreate the directory.

The Lockfile

project.lock records the exact version that every package was resolved to, whether it's a direct dependency or not, along with where it came from and the checksum of what was downloaded:

zuri restore installs exactly what the lockfile lists. It's what you run after a fresh checkout, and what a teammate or a build server runs:

A package whose download doesn't match its recorded checksum is rejected. --frozen stops with an error if the lockfile no longer matches project.toml, instead of resolving the dependencies again, which is what you want for a build that must install exactly what was reviewed. --production leaves out anything that only development dependencies need.

zuri install without a package name does the same as zuri restore after you've changed project.toml. It only resolves what changed, and keeps every other package at its locked version.

Conflicting Requirements

Every package gets exactly one version, chosen so that every requirement in the project is satisfied at the same time. When that's not possible, the install stops without changing anything, and explains the conflict step by step:

Read it from the bottom up: report-kit needs version 2 of json-schema, http-extra needs version 1, and a project can't have both. To fix it, use a newer version of http-extra that accepts version 2 of json-schema, if one exists, or stop using one of the two packages.

Updating Packages

current is the installed version, wanted is the newest version the declared range allows, and latest is the newest version available, marked when updating to it could break code written against the current version.

--latest changes the range in project.toml to the newest release, keeping an exact range exact, and points out every update to a new major version.

Removing Packages

Anything that was only installed because the package needed it is removed as well. A package that something else still needs is kept, and zuri uninstall tells you what needs it.

Getting Information About Packages

A package whose declared range, locked version and installed version don't agree is marked with one of these states: missing, drifted, unlocked or extraneous. With --verify, a package whose files have changed since it was installed is marked as modified.

You can also ask the registry for information:

Git and Local Packages

A package doesn't have to come from a registry:

The package's name is taken from its own project.toml. A git dependency is locked to the commit that its tag, branch or revision pointed to, and to the checksum of that commit's packaged files, so zuri restore installs the same files even after the branch has moved on. zuri update updates a branch dependency to its newest commit. A path dependency is copied again every time the project is installed, which suits a package that you're working on alongside the project that uses it.

A published package can only depend on packages from a registry, because a git or path dependency wouldn't mean anything on the machine of whoever installs it.

Other Registries

Packages are installed from the default registry, https://pub.zurilang.org, unless you say otherwise:

The dependency records which registry it came from, so everyone who installs the project gets it from the same place. A project that uses a registry often can give it a name once:

You can also define aliases in $ZURI_HOME/config.toml, for your own use in every project. Setting default there, or setting ZURI_REGISTRY in the environment, changes the registry that's used when none is named, although a project that defines its own default keeps using it.

A package is never installed from a different registry as a fallback. A package requested from one registry is only ever installed from that registry, so a package with the same name on another registry can never be substituted for it.

Install Scripts

A package can specify scripts to run before and after it's installed:

A script can do anything that the person running zuri install can do, so a dependency's scripts only run if the project allows that package by name:

The project's own scripts always run. --allow-hooks allows more packages for a single run, and --no-hooks doesn't run any scripts. A script runs with zuri run, from the package's directory, without a shell in between, and it has to finish within ten minutes with status 0. Its output goes to a log file under $ZURI_HOME/logs, which is named in the error if the script fails. ZURI_PACKAGE_NAME, ZURI_PACKAGE_VERSION, ZURI_PACKAGE_DIR and ZURI_PROJECT_DIR tell the script where it's running. If a script fails, the whole install is undone.

Working Offline, Caches and Disk Space

Downloads are kept in a cache, checked against their checksums, and shared by every project on the machine. --offline installs packages from the cache only, and if something's missing, it fails with an error that names what's missing instead of using the network.

Anything that zuri clean removes comes back automatically the next time it's needed, either downloaded again or restored from the lockfile.

Environment Variables

Variable What it does
ZURI_HOME Where your packages, settings and tokens are stored. The default is ~/.zuri.
ZURI_CACHE Where downloads are cached. The default is $ZURI_HOME/cache.
ZURI_REGISTRY The default registry, as an alias or an address
ZURI_TOKEN, ZURI_TOKEN_<ALIAS> A registry token, which takes priority over the saved one
HTTPS_PROXY, HTTP_PROXY, NO_PROXY The proxy used for every download
NO_COLOR Turns off colored output
