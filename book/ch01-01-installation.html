1.1 · Getting Started

Installation

You can install Zuri with a single command. The installer downloads the right release for your machine, verifies it, and adds zuri to your PATH. Releases are available for:

  • Linux on x86-64 and ARM with the GNU C library 2.28 or later (x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu). This includes Debian 10, Ubuntu 20.04, RHEL 8, Amazon Linux 2023 and newer versions of each.
  • Linux on x86-64 and ARM with musl, such as Alpine (x86_64-unknown-linux-musl, aarch64-unknown-linux-musl)
  • macOS on Intel and Apple silicon (x86_64-apple-darwin, aarch64-apple-darwin)
  • Windows on x86-64 (x86_64-pc-windows-msvc)

You can also build Zuri from source with Cargo, as described at the end of this page.

Linux and macOS

The installer downloads the archive for your machine and checks it against the checksum published with it. Next, it runs the new zuri once to make sure it reports the expected version. Only then does it move the files into ~/.zuri/runtime, so a failed or tampered download can't replace a working installation. The installer links zuri into ~/.zuri/bin, which is also where globally installed tools put their launchers, and adds that directory to your PATH in your shell's startup file. That's .zshrc for zsh, .bashrc for bash (.bash_profile on macOS), config.fish for fish, and .profile for any other shell.

On Linux distributions that use musl, the installer picks the musl build, which runs on a plain Alpine system without any extra packages. It loads shared libraries the same way Alpine's own programs do. That's what allows ffi to open them, and it's also why the build needs the musl loader to be present. The musl build doesn't run on Linux systems that use the GNU C library.

To pass options to the installer, put them after sh -s --:

Option What it does
--version <version> Installs the given release instead of the newest one
--prerelease Includes pre-releases when looking for the newest release
--no-modify-path Leaves your shell's startup files unchanged

Where Zuri Is Installed

Both installers put everything under ZURI_HOME. Unless you set that variable, it's the .zuri directory in your home directory:

runtime contains the executable, with copies of the libs and cmds directories next to it. The two need to stay together. Most of the standard library is written in Zuri, and the runtime finds it by looking for a libs directory next to the executable. cmds works the same way for the commands that come with the runtime.

Running an installer again installs over the existing copy. zuri upgrade does the same thing from inside an installation, as described in Bundles and Upgrades. To remove Zuri, delete ~/.zuri/runtime and the zuri link in ~/.zuri/bin, and remove the line the installer added to your shell's startup file.

If you set ZURI_RELEASES_URL, both installers and zuri upgrade read the list of releases from that address instead, for example from a mirror. The listing has to use the same format that GitHub does. If GITHUB_TOKEN is set, it's sent along with requests to GitHub's API, which gives you a higher rate limit.

Downloading a Release Manually

Each release on the releases page has one archive per platform, named zuri-<version>-<target>.tar.gz (or .zip on Windows), and a .sha256 file next to it. Verify the archive against the checksum, unpack it, and add the zuri executable it contains to your PATH. Keep the libs and cmds directories next to the executable.

Building From Source

To build Zuri, you need Cargo, Rust's package manager. If you don't have Rust installed, you can get it from rustup.rs. It only takes a minute, and it installs cargo for you.

cargo patch-crates prepares the few dependencies that Zuri builds with its own changes. You need to run it once after cloning the repository, and again only when one of those changes is updated. The build tells you when that happens.

The first build compiles a large number of native dependencies, so expect it to take a few minutes. Later builds are incremental and much faster.

When the build finishes, you'll have an executable at target/release/zuri, with copies of the libs/ and cmds/ directories next to it, arranged the same way as in a release.

Debug Builds

A plain cargo build produces target/debug/zuri. This build keeps the runtime assertions that the optimized build removes, which makes it useful when a program does something you didn't expect. The trade-off is that it runs more slowly. Both builds can run everything in this book.
