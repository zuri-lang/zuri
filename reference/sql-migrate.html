Databases

sql.migrate

sql does not re-export this module, so it is reached only by importing it directly.

Versioned changes to a database's schema, applied once each, in order, on every engine.

A migration is a Zuri file in a directory of them. Its name starts with a version, a run of digits, and says what it does:

Each exports up(db), which makes the change, and down(db), which undoes it. db is the Transaction the migration runs in, or the Connection itself where it runs outside one: always on MySQL and MariaDB, and anywhere for a migration that asks to. Its type is Transaction|Connection, and the change is described with db.schema and its Blueprint, once, for every engine the program runs against:

Migrator applies what a database has not had and rolls back what it has, and records each one in a table of its own, zuri_migrations by default:

zuri migrate does the same from the command line.

How a migration runs

Each migration runs in a transaction of its own, together with the row recording it, so on SQLite and PostgreSQL a migration that fails part way leaves nothing behind and is not recorded. MySQL and MariaDB commit at every schema change: there a migration runs on its own and is recorded once it has finished, and one that fails part way leaves the statements before the failure in place.

On SQLite, foreign key enforcement is switched off while a migration runs, so a change that builds a table again cannot take the rows referring to it along, and every foreign key is checked before the migration commits.

A migration that has to run outside a transaction, as PostgreSQL's create index concurrently does, says so:

Several processes at once

Two processes migrating one database at the same moment apply each migration once. On PostgreSQL, MySQL and MariaDB a run holds the engine's own lock, and a second run waits for the first to finish. On SQLite each migration takes the write lock as it starts, and every migration checks the record again once it holds the lock, so one another process applied meanwhile is passed over.

Batches

Every migration one up() applies shares a batch number, and down() with no options rolls back the latest batch whole: what the last run applied, however many that was.

The table a Migrator records migrations in unless told another.

DEFAULT_DIRECTORY

The directory a Migrator reads migrations from unless told another, relative to the working directory.

Functions

is_name()

Whether name can name a migration: one or more letters, digits and underscores, such as create_posts.

Parameters

  • name (string)

Returns bool

create()

Writes a new, empty migration into directory, and returns its path.

The version is the moment it was made, in UTC, as YYYYMMDDHHMMSS, moved on a second at a time past any version the directory already holds. The file is the version, an underscore and name, exactly as given.

A name of the form create_<table> starts the migration creating that table, with an id() and timestamps(), and dropping it on the way down. Any other name starts it empty. Either way up() and down() start typed, db: Transaction|Connection, with the classes imported from sql.

Parameters

  • directory (string) — Created when it is not there.
  • name (string) — Letters, digits and underscores.

Returns string — The new file's path.

Raises MigrationError if name is empty or has anything but letters, digits and underscores in it, and nothing is written.

Migrator

Applies a directory of migrations to one database, and rolls them back.

The record of what has been applied lives in the database, in the table table names, created the first time a Migrator needs it.

  • printable — has a @to_string(), so echo and print() show something useful

Fields

Field Type Description
connection Connection The connection migrated.
directory string The directory the migrations are read from.
table string The table migrations are recorded in.

Constructor

Parameters

  • connection (Connection) — A connection of its own: a run holds it, and on PostgreSQL and MySQL a session lock on it, from start to finish. A connection taken from a pool is returned to it afterwards by the caller, as any other.
  • options (dict|nil) — directory, the directory of migrations, migrations by default; and table, the table recording them, zuri_migrations by default.

Migrator.migrations()

Every migration in the directory, in the order they apply: by version, then by name.

A .zu file whose name starts with _ is not a migration, which is where code several migrations share goes. Files that are not .zu are left alone.

Returns list[Migration]

Raises MigrationError if the directory is not there, a file's name does not start with a version and an underscore, or two files share a version.

Migrator.applied()

What the database records as applied, oldest first. Each is { name, batch, checksum, applied_at }.

Returns list[dict]

Migrator.pending()

The migrations the database has not had, in the order they apply.

Returns list[Migration]

Migrator.status()

Every migration, in a file or in the record or both, with what is known about it. Each is { name, state, batch, applied_at }, and state is one of:

State Meaning
applied recorded, and the file is as it was when it ran
changed recorded, and the file has changed since it ran
missing recorded, and there is no file for it any more
pending a file the database has not had

batch and applied_at are nil for a pending migration.

Returns list[dict]

Migrator.up()

Applies pending migrations, in order, as one batch.

A migration that fails stops the run where it is. Those before it stay applied, and it and those after it stay pending.

Parameters

  • options (dict|nil) — steps, how many to apply at most; or to, the name of the last one to apply. Everything pending when neither is given.

Returns list[string] — The names applied, in order.

Raises MigrationError if to names no pending migration, or a file cannot be run.

Migrator.down()

Rolls applied migrations back, newest first.

Every migration about to be rolled back is checked first: each has to have its file, with a down(), or nothing is rolled back at all.

Parameters

  • options (dict|nil) — steps, how many to roll back; or to, the name of a migration to leave as the latest applied, rolling back everything after it. The latest batch when neither is given.

Returns list[string] — The names rolled back, in the order they were.

Raises MigrationError if to names no applied migration, or one to be rolled back has no file or no down().

Migrator.reset()

Rolls back every applied migration, newest first.

Returns list[string] — The names rolled back.

Raises MigrationError if one has no file or no down(); nothing is rolled back then.
