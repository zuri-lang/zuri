The Machine

args

A framework for building command-line interfaces. It supports options (flags), positional arguments, subcommands with their own options, automatically generated help, type conversion, required arguments, deprecation warnings, choices, abbreviated long options, -- to end the options, and @file arguments.

Passing a value to an option

A long option takes its value either as the next argument or after an =. Both mean the same thing:

The argument is split at the first =, so --path=a=b sets path to a=b. The = form is the only way to pass a value that starts with a dash, because --name -5 reads -5 as an option:

A short option only takes its value as the next argument. -n Alice works, but -n=Alice doesn't, because a short argument is a group of single-character flags, and = isn't one of them. Every character in the group has to name an option, so a typo in -vq is an error, instead of a flag that's silently ignored.

Constants

NONE

Value type for an option that takes no value. The option is true when it's given.

INT

Value type for an integer. A value such as 3.7 has its fractional part dropped.

NUMBER

Value type for a number, which can have a fractional part.

BOOL

Value type for a boolean. The value can be true, false, 1, 0, yes, no, on or off, in any case.

STRING

Value type for a string. This is the default type of a positional argument.

LIST

Value type for a list. The option takes every word after it up to the next word that starts with -, and it can be given more than once to add to the list.

CHOICE

Value type for a value that has to be one of the choices. If choices is a dictionary, the value given has to be one of its keys, and the result is the value that the key maps to.

OPTIONAL

Value type for an option whose value can be left out. The option takes the next word as its value unless that word starts with -, and it's true when it has no value.

Classes

ArgsError

Raised when a parser is set up incorrectly, such as when two options have the same name, or when a default value can't be converted to its option's type.

Mistakes on the command line aren't raised. The parser prints the error and the help text instead, and ends the program with exit status 1.

Parser

A command-line parser.

Properties

These can be set after the parser is created:

  • description (string): a paragraph shown in the help text, after the usage line.
  • epilog (string): a paragraph shown at the end of the help text.
  • allow_abbrev (bool): whether a long option can be shortened to any prefix that matches only one option, as in Python's argparse. Defaults to true.
  • allow_atfile (bool): whether an argument such as @args.txt is replaced by the arguments read from that file. Defaults to true.

Parser.set_terminal_width()

Sets the width that the help text wraps to, in place of the width that the parser detected when it was created. Use it to get the same layout in any terminal, which tests usually need.

This does the same as setting terminal_width, except that it raises a TypeError if width isn't a positive number.

Parameters

  • width (number)

Parser.add_option()

Adds a global option to the parser. A global option can be given before or after a command.

These keys can be given in opts:

  • short_name (string): a single-character alias, used as -x.
  • type (int): one of the value types, such as INT or LIST. Defaults to NONE.
  • value (any): the value to use when the option isn't given.
  • choices (list or dict): the values allowed for an option of type CHOICE.
  • required (bool): whether parse() reports an error when the option isn't given.
  • metavar (string): the placeholder for the value in the help text. Defaults to the option's name in lowercase.
  • deprecated (bool): whether to print a warning when the option is used.

Parameters

  • name (string)
  • help (?string)
  • opts (?dict)

Parser.add_command()

Adds a subcommand.

These keys can be given in opts:

  • type (int): the type of the command's value, if it takes one.
  • action (function): a function to call after parsing, with the options and the command's value.
  • choices (list or dict): the values allowed when type is CHOICE.
  • metavar (string): the placeholder for the command's value in the help text, such as 'message' for git commit -m <message>. Defaults to the name of the value's type, in lowercase.

Returns the new command. Its add_option() returns the command too, so the calls can be chained:

Parameters

  • name (string)
  • help (?string)
  • opts (?dict)

Returns — _Command

Parser.add_index()

Adds a positional argument.

These keys can be given in opts:

  • type (int): one of the value types. Defaults to STRING.
  • value (any): the value to use when the argument isn't given.
  • choices (list or dict): the values allowed when type is CHOICE.
  • required (bool): whether parse() reports an error when the argument isn't given. Defaults to false.
  • metavar (string): the name shown for the argument in the help text.

If a positional argument has no value and isn't given, it's left out of the indexes that parse() returns. It isn't added as nil.

A positional argument of type LIST takes every remaining positional word on the command line, including words that come after options, and it appears in indexes as a single list. It has to be the last positional argument added.

Parameters

  • name (string)
  • help (?string)
  • opts (?dict)

Raises ArgsError if a positional argument is added after one of type LIST.

Parser.parse()

Parses the command line, and returns a dictionary with the options, the command and the positional arguments.

By default, this reads the arguments the program was started with, from os.args, leaving out the interpreter and the script path. Pass custom_args, a list of strings, to parse a different list, such as one built from a configuration file or a fixed list in a test.

indexes has one entry for each positional argument that has a value, in the order they were added. That's each argument that was given, followed by the default value of any that weren't. An argument that wasn't given and has no default value is left out instead of being added as nil.
