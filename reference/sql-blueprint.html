The Zuri Standard Library

sql.blueprint

import sql.blueprint

sql lifts part of this module out to its own top level; each name below is shown with the path that reaches it. Anything still spelled sql.blueprint.* needs import sql.blueprint.

A table’s shape, described once for every engine.

A Blueprint is what db.schema.create_table() and db.schema.alter_table() hand their body: a description of columns, keys and indexes in Zuri, which the active adapter turns into the statements its own engine understands. The same blueprint creates the same table on SQLite, PostgreSQL, MySQL and MariaDB, which is what lets one migration serve every database a program runs against.

db.schema.create_table('posts', @(table: Blueprint) {
  table.id()
  table.references('author_id', 'authors').on_delete('cascade')
  table.string('title', 200)
  table.text('body').nullable()
  table.boolean('published').default_value(false)
  table.timestamps()
  table.index('published')
})

An id() is never handed out twice, even after the row holding the highest one is deleted. A decimal() on SQLite holds at most 15 significant digits, the most a double keeps exactly, so a larger precision raises NotSupportedError there rather than storing digits that would quietly change.

Columns are required unless they say otherwise

Every column is NOT NULL until nullable() says it may hold nothing. A missing value is then an error the database reports, rather than a null nobody meant to store.

Names

Indexes, unique indexes and foreign keys are named for their table and columns: posts_author_id_index, posts_slug_unique, posts_author_id_foreign. Because the name is known, dropping one takes its columns as readily as its name. A name past 63 characters, the longest PostgreSQL keeps, is shortened and given a hash of the whole so it stays unique.

Constants

CASCADE

sql.blueprint.CASCADE = 'cascade'

Deletes the rows that refer to a deleted row.

RESTRICT

sql.blueprint.RESTRICT = 'restrict'

Refuses to delete a row while others refer to it.

SET_NULL

sql.blueprint.SET_NULL = 'set null'

Sets the referring column to null.

SET_DEFAULT

sql.blueprint.SET_DEFAULT = 'set default'

Sets the referring column to its default.

NO_ACTION

sql.blueprint.NO_ACTION = 'no action'

Does nothing at the moment of the change, and refuses it at the end of the statement if a reference is left dangling. What a foreign key does when it names no action.

ACTIONS

sql.blueprint.ACTIONS = [...]

Every action on_delete() and on_update() accept.

MAX_NAME

sql.blueprint.MAX_NAME = 63

The longest name every engine keeps whole.

Functions

index_name()

sql.blueprint.index_name(table: string, columns: list, suffix: string) -> string

The name an index or key on columns of table takes.

suffix is index, unique, foreign or primary. The table’s own name is used without any schema in front of it, and a name past MAX_NAME characters is cut short and finished with eight characters of a hash of the whole, so two long names that share a beginning still differ.

index_name('posts', ['author_id', 'created_at'], 'index')
# posts_author_id_created_at_index

Parameters

  • table (string)
  • columns (list[string])
  • suffix (string)

Returns string

ForeignKey

class sql.ForeignKey

A foreign key: the columns of one table that refer to rows of another.

Made by Blueprint.foreign(), or by Column.references() for a key of one column. The actions say what happens to a referring row when the row it refers to is deleted or has its key changed. With none given, the engine refuses the change while references remain.

Column

class sql.Column

One column, as a blueprint describes it.

Every column method on Blueprint returns one of these, and every method here returns the column again, so a column is described in one chain:

table.string('email', 254).exact().unique()
  • printable — has a @to_string(), so echo and print() show something useful

Column.default_value()

sql.Column.default_value(value) -> Column

Gives the column a default, used when an insert leaves it out.

The value is written into the table definition as a literal of the column’s type: a string, a number, a bool, nil, a sql.Decimal, or for a json() column a list or dictionary. A sql.Raw is written as given, for a default that is an expression rather than a value; it is SQL, and the engine reads it as such.

Column.exact()

sql.Column.exact() -> Column

Compares the column byte for byte, so case and accents always count: 'Ada' and 'ada' are two values, and so are 'é' and 'e'.

SQLite compares this way already. PostgreSQL is given the "C" collation and MySQL and MariaDB utf8mb4_bin, whose default collations treat case, and on MySQL accents, as the same. Use it for a column that holds a key, where two values differing only in case must not collide or match each other.

Returns Column

Raises QueryError on a column that does not hold text.

Column.references()

sql.Column.references(table: string, column) -> Column

Makes the column refer to a row of another table.

The column’s values have to be the referred column’s values, or null on a nullable column. on_delete() and on_update() on this column then say what happens when the referred row changes.

Column.change()

sql.Column.change() -> Column

Turns this into a change to a column the table already has, inside alter_table().

The column takes the type, nullability, default and comparison declared here, whatever it had before, so declare it in full: leaving out nullable() makes it required. Its indexes stay as they are, and unique() or index() here adds one.

db.schema.alter_table('posts', @(table: Blueprint) {
  table.string('title', 300).change()
})

Returns Column

The description of one table, or of the changes to one.

db.schema.create_table() and db.schema.alter_table() make one and pass it to their body, then hand it to the adapter, which carries out what it describes in the order it was described. A program does not build one itself.
