The Zuri Standard Library

sql.model.record

import sql.model.record

sql lifts part of this module out to its own top level; each name below is shown with the path that reaches it. Anything still spelled sql.model.record.* needs import sql.model.record.

The class every model extends, and what a record does: save itself, delete itself, check itself, and reach the records it is associated with.

A record never holds a connection. Every method that touches the database takes the connection or transaction to use, so a record loaded on one connection saves on whichever the code saving it is using, a transaction included, and one kept after its connection was closed or returned to a pool cannot write through it by accident.

Classes

Model

class sql.model.Model

The class a model extends.

class Post < Model {
  var id
  var title
  var published = false
  var created_at
  var updated_at

  static define(model: Definition) {
    model.timestamps()
    model.validate('title', validate.required().string().max_length(200))
  }

  before_save(db) {
    self.title = self.title.trim()
  }
}

Calling the class builds a new record, from a dictionary of attributes when one is given, which are assigned as fill() assigns them. Records loaded from the database are built the same way, with no arguments, so a model’s own @new takes no required arguments, and calls parent(attributes) when it takes attributes.

Hooks

A model overrides any of these to run code at that point of a record’s life. Each is handed the connection or transaction the record is going through, and when a model has any of them, saving and deleting run in a transaction, a savepoint inside an open one, so what a hook writes is undone with the rest when anything fails. A hook raises to stop the save or the delete.

HookRuns
before_validate(db)before the record is checked
validate(errors)as it is checked, to add failures of the model’s own
after_validate(db)after it is checked, whatever was found
before_save(db)before it is written, new or not
before_create(db)before a new record is inserted
after_create(db)after it is inserted, with its key
before_update(db)before a saved record’s changes are written
after_update(db)after they are written
after_save(db)after it is written, new or not
before_delete(db)before it is deleted
after_delete(db)after it is deleted
after_load()as a record is built from a row

A model’s methods share a namespace with these and with the methods below, so a model does not declare a method of the same name as one of them for anything else. A field may share a name with any of them.

  • printable — has a @to_string(), so echo and print() show something useful

Model.fill()

sql.model.Model.fill(attributes: dict, only) -> Model

Assigns attributes from a dictionary, as a form or a request body supplies them.

Only fillable columns are assigned: those the model lists with fillable(), or every column but the primary key and the timestamps when it lists none. That is what keeps a request from setting a record’s key, or a column it was never meant to reach.

post.fill(request.form(), ['title', 'body'])

Parameters

  • attributes (dict)
  • only (list[string]|nil) — The keys to take from attributes, leaving the rest. Every key when nil.

Returns Model — The record, for chaining.

Raises ModelError for a key taken that is not fillable.

Model.save()

sql.model.Model.save(db) -> Model

Saves the record: inserts it when it is new, writes its changes when it is not.

It is checked first, and not written when it fails. A new record leaves out every column still nil, so the database’s default fills it, then reads those columns back, so the record holds what was stored. A record already saved writes only the columns that changed, and nothing at all when none did. A record held in a belongs_to association sets the column referring to it.

Parameters

  • db (Connection|Transaction)

Returns Model — The record.

Raises RecordInvalid if it fails its checks.

Raises ModelError if a record it belongs to has not been saved.
