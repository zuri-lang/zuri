Databases

sql.postgres.messages

sql does not re-export this module, so it is reached only by importing it directly.

Framing for the PostgreSQL wire protocol, version 3.

Every message is a one byte tag, a four byte big-endian length that counts itself, and then the body. The one exception is the startup message, which has no tag because the server has not yet been told which protocol version is in use.

PROTOCOL_VERSION

The protocol version this adapter speaks: 3.0, as a single number with the major version in the high half.

SSL_REQUEST

The number the server recognises as a request to start TLS. It takes the place of a protocol version in a startup-shaped message.

READ_SIZE

How much a Reader asks the stream for at a time.

Functions

frame()

A finished message from a body already built.

The same framing Writer.frame() gives, for a body put together without a Writer.

Parameters

  • tag (string)
  • body (bytes)

Returns bytes

read_cstring()

Splits a run of zero-terminated strings.

Several messages are built this way, including the error report, where each field is a one byte code followed by its text.

Parameters

  • payload (bytes)
  • at (number) — Where to start.

Returns dict — { value, next }

Reader

Reads framed messages from a connected stream.

Works over a plain TcpStream or a TlsStream without caring which, since both read the same way. Reads are buffered: one read from the stream usually brings in every message of a reply, and the messages are then taken from the buffer.

Fields

Field Type Description
buffer bytes What has been read from the stream and not yet taken, with the body of the message next_message() last...
start number Where the body of the message next_message() last returned starts in buffer.
end number Where that body ends in buffer, exclusive.

Constructor

Parameters

  • stream (TcpStream|TlsStream) — An already-connected stream.

Reader.upgrade()

Swaps the stream, for the point in the handshake where a plain connection becomes a TLS one.

Parameters

  • stream (TlsStream)

Raises ConnectionError if bytes the server sent before the handshake are still unread. They arrived in the clear, so nothing that follows may treat them as protected.

Reader.read_exact()

Reads exactly count bytes, waiting for as many as it takes.

Parameters

  • count (number)

Returns bytes

Raises ConnectionError if the server closes first.

Reader.next_message()

Reads the next message and returns its tag as a number, leaving its body where it arrived: from start to end in buffer.

Nothing is copied, which is what a reply of many rows wants. The body is only there until the next read; read_message() is the form to use for one that has to outlast it.

Returns number — The tag's byte, such as 68 for a DataRow.

Raises ConnectionError if the server closes first.

Reader.read_message()

Reads the next message as a copy of its own.

Returns dict — { tag, payload }

Raises ConnectionError if the server closes first.
