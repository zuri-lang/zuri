The Zuri Standard Library

sql.ddl

import sql.ddl

sql lifts part of this module out to its own top level; each name below is shown with the path that reaches it. Anything still spelled sql.ddl.* needs import sql.ddl.

Turning a Blueprint into the statements one engine understands, and running them the way that engine needs them run.

Every engine spells a table differently. An auto-numbered key is autoincrement to SQLite, an identity column to PostgreSQL and auto_increment to MySQL; a byte-for-byte comparison is SQLite’s default, PostgreSQL’s "C" collation and MySQL’s utf8mb4_bin; and a change SQLite’s ALTER TABLE cannot make has to be carried out by building the table again. DdlAdapter holds what is the same for all of them, and each adapter’s subclass supplies the rest.

A program never calls this directly. db.schema.create_table() and the other schema changes go through Driver.ddl(), and an adapter of one’s own subclasses DdlAdapter and returns it from its driver’s ddl() to get them.

Running a change

Each method takes the Connection to change and runs its statements on it. schema_change() is the envelope a change runs in when the caller has no transaction open, and what sql.migrate runs every migration in: a transaction on an engine that can roll a schema change back, nothing on one that cannot, and on SQLite foreign key enforcement switched off around it, checked again before it commits.

Classes

DdlAdapter

class sql.DdlAdapter

Turns blueprints into one engine’s statements and runs them.

The methods a subclass overrides fall into two groups. What the engine calls things: type_name(), key_definition(), exact_collation(), boolean_literal(), string_literal(), current_default(), table_suffix(), parenthesised_default() and inline_indexes(). And how the engine changes a table that exists: change_column(), drop_column(), drop_index(), drop_foreign() and drop_primary(). The defaults are standard SQL, and raise NotImplementedError where there is no standard to fall back on.
